## 1. Как работает сайт: браузер, сервер, домен, хостинг
🇮🇹 *Come funziona un sito: browser, server, dominio, hosting*

**Простое объяснение.** Представь, что сайт — это магазин.

| Понятие | 🇮🇹 Итальянский | Аналогия | Что это на самом деле |
|---|---|---|---|
| Браузер (browser) | *il browser* | Покупатель, который идёт в магазин | Программа на телефоне/компьютере (Chrome, Safari), которая запрашивает и показывает страницы |
| Сервер (server) | *il server* | Сам магазин со складом | Компьютер, который всегда включён и отдаёт файлы сайта по запросу |
| Домен (domain) | *il dominio* | Адрес магазина: «ул. Мадзини, 10» | Человекочитаемое имя: `pizzeriadamario.it` |
| Хостинг (hosting) | *l'hosting* / *lo spazio web* | Аренда помещения | Услуга, которая даёт место на сервере (у тебя — Vercel) |
| IP-адрес | *indirizzo IP* | GPS-координаты магазина | Числовой адрес сервера, например `76.76.21.21` |

**Что происходит, когда клиент набирает адрес сайта:**

1. Человек пишет `pizzeriadamario.it` в браузере.
2. Браузер спрашивает у DNS (🇮🇹 *sistema dei nomi di dominio*, «телефонная книга интернета»): «Какой IP у этого домена?»
3. DNS отвечает: «76.76.21.21» (это сервер Vercel).
4. Браузер обращается к серверу и просит файлы страницы.
5. Сервер отдаёт HTML, CSS, JavaScript, картинки.
6. Браузер собирает из них страницу и показывает её.

Всё это занимает доли секунды.

**Пример из твоей работы.** Ты сделал сайт для парикмахерской в Вероне. Код лежит на GitHub, Vercel его «публикует» (то есть хранит на своих серверах), а домен `barbieriverona.it` клиент купил на Aruba. В DNS Aruba ты указываешь: «этот домен ведёт на Vercel». Клиент открывает домен — и видит твой сайт.

✅ **Что нужно знать для работы**
1. Домен, хостинг и сайт — три разные вещи, которые можно покупать у разных компаний.
2. Браузер ничего «не хранит» навсегда — он каждый раз запрашивает файлы у сервера (с кэшем, но об этом позже).
3. Если сайт «не открывается», проблема может быть в одном из трёх мест: домен/DNS, сервер/хостинг, код сайта.

❓ **Вопрос для самопроверки:** Если клиент сменит хостинг, нужно ли ему менять домен?
*(Ответ: нет. Меняются только DNS-записи, которые указывают на новый сервер.)*

⚠️ **Типичная ошибка:** Думать, что «купить сайт на Aruba» = «купить домен». У Aruba можно купить только домен, а сайт держать на Vercel.

## 2. HTML, CSS, JavaScript
🇮🇹 *HTML, CSS, JavaScript: struttura, stile, comportamento*

**Аналогия с человеком:**

| Технология | 🇮🇹 | Аналогия | Что делает |
|---|---|---|---|
| **HTML** | *linguaggio di markup* | **Скелет** | Определяет структуру и содержание: заголовки, абзацы, картинки, кнопки |
| **CSS** | *fogli di stile* | **Одежда** | Определяет внешний вид: цвета, шрифты, отступы, расположение |
| **JavaScript (JS)** | *linguaggio di programmazione / script* | **Поведение (мышцы и нервы)** | Добавляет действия: меню открывается, форма проверяется, галерея листается |

**Как это выглядит:**

```html
<!-- HTML: скелет -->
<h1>Pizzeria da Mario</h1>
<p>La vera pizza napoletana a Verona.</p>
<button id="chiama">Chiama ora</button>
```

```css
/* CSS: одежда */
h1 { color: #b22222; font-size: 40px; }
button { background: green; color: white; padding: 12px 24px; }
```

```javascript
// JavaScript: поведение
document.getElementById("chiama").onclick = function () {
  window.location.href = "tel:+390451234567";
};
```

- `<h1>` — главный заголовок (🇮🇹 *titolo principale*).
- `<p>` — абзац (🇮🇹 *paragrafo*).
- `<button>` — кнопка (🇮🇹 *pulsante*).
- В CSS `color` — цвет текста, `padding` — внутренний отступ (🇮🇹 *spaziatura interna*).
- В JS: «когда нажали на кнопку — позвони по номеру».

**Пример из твоей работы.** Клиент говорит: «Хочу, чтобы кнопка была красной». Это CSS. «Хочу добавить раздел “Наши услуги”» — это HTML. «Хочу, чтобы при нажатии открывался WhatsApp» — это ссылка в HTML (`https://wa.me/39...`) или JS.

Когда пишешь промпт в Claude Code, ты будешь точнее, если знаешь, к чему относится изменение: «Измени стиль кнопки (CSS)» вместо «сделай красиво».

✅ **Что нужно знать для работы**
1. Любой сайт в браузере в итоге — это HTML + CSS + JS, даже если сделан на React.
2. Текст и картинки — в HTML; внешний вид — в CSS; действия — в JS.
3. Можно сделать хороший сайт для малого бизнеса почти без JavaScript.

❓ **Вопрос для самопроверки:** Клиент хочет поменять шрифт на всём сайте. Какой файл (технологию) нужно менять?
*(Ответ: CSS.)*

⚠️ **Типичная ошибка:** Добавлять много JavaScript (анимации, слайдеры, эффекты) туда, где он не нужен. Это замедляет сайт на телефоне и ничего не даёт клиенту.

## 3. Что такое фреймворк (React, Next.js) и почему он нужен не всегда
🇮🇹 *Cos'è un framework e perché non sempre serve*

**Простое объяснение.** Фреймворк (🇮🇹 *framework*, иногда *struttura di sviluppo*) — это готовый «конструктор» с правилами и деталями, который ускоряет создание сложных сайтов и приложений.

- **React** — библиотека для создания интерфейса из «кубиков»-компонентов (🇮🇹 *componenti*). Например, компонент «Карточка услуги» пишется один раз и используется 10 раз.
- **Next.js** — фреймворк поверх React, который добавляет страницы, маршруты (🇮🇹 *rotte / routing*), SEO-функции, оптимизацию картинок. Его создала компания Vercel, поэтому они отлично работают вместе.
- **Astro** — фреймворк для быстрых сайтов с контентом; отдаёт почти чистый HTML. Отличный выбор для «сайтов-визиток».

**Аналогия.** Чтобы построить сарай, не нужен башенный кран. Чтобы построить 20-этажный дом — нужен.

| Тип проекта | 🇮🇹 | Что выбрать |
|---|---|---|
| Сайт-визитка (5 страниц: главная, услуги, о нас, галерея, контакты) | *sito vetrina* | Чистый HTML/CSS или Astro |
| Сайт с блогом, который клиент обновляет | *sito con blog* | Astro или Next.js + CMS |
| Интернет-магазин | *e-commerce / negozio online* | Shopify, WooCommerce или Next.js + Shopify |
| Приложение с логином, личным кабинетом | *web app / area riservata* | Next.js |

**Пример из твоей работы.** Для пиццерии с меню и кнопкой «позвонить» достаточно HTML/CSS или Astro. Если Claude Code по умолчанию создаёт проект на Next.js — это не ошибка, но больше «движущихся частей», которые могут сломаться при обновлениях. В промпте можно прямо написать: «Сделай статический сайт на чистом HTML и CSS, без фреймворка».

✅ **Что нужно знать для работы**
1. Фреймворк — инструмент, а не признак «профессионального» сайта. Клиенту важен результат.
2. Чем проще стек (🇮🇹 *stack tecnologico*), тем дешевле и спокойнее поддержка.
3. Next.js оправдан, когда есть динамика: формы с логикой, личные кабинеты, много страниц из базы данных.

❓ **Вопрос для самопроверки:** Нужен ли Next.js для одностраничного сайта с номером телефона и картой? Почему?

⚠️ **Типичная ошибка:** Выбирать сложный фреймворк «потому что так делают все», а потом не понимать ошибок сборки (🇮🇹 *errori di build*), когда что-то обновилось.

## 4. Git и GitHub: commit, push, branch, deploy
🇮🇹 *Git e GitHub: commit, push, branch, cosa significa "deploy"*

**Простое объяснение.**

- **Git** — программа, которая сохраняет историю изменений файлов. Как «сохранения» в видеоигре: можно вернуться к любой точке.
- **GitHub** — сайт, где хранится копия этой истории в интернете (в облаке). 🇮🇹 *piattaforma per ospitare il codice*.
- **Репозиторий (repository, repo)** — папка проекта со всей историей. 🇮🇹 *repository* / *archivio del progetto*.

| Термин | 🇮🇹 | Что значит | Аналогия |
|---|---|---|---|
| **commit** | *commit* / *salvataggio* | Сохранить «снимок» изменений с описанием | Точка сохранения в игре с подписью «добавил меню» |
| **push** | *push* / *inviare* | Отправить коммиты с компьютера на GitHub | Загрузить сохранения в облако |
| **pull** | *pull* / *scaricare* | Забрать изменения с GitHub к себе | Скачать сохранения из облака |
| **branch** | *ramo* | Параллельная версия проекта | Черновик, который не трогает чистовик |
| **main** | *ramo principale* | Основная ветка — то, что на «живом» сайте | Чистовик |
| **merge** | *unire* | Объединить ветку с основной | Перенести черновик в чистовик |
| **pull request (PR)** | *richiesta di modifica* | Запрос на объединение с возможностью проверить изменения | «Посмотри черновик, прежде чем переписать в чистовик» |
| **deploy** | *pubblicazione / messa online* | Опубликовать сайт на сервере, чтобы его увидели люди | Открыть двери магазина |

**Как это выглядит в твоём процессе:**

```
Ты пишешь промпт → Claude Code меняет файлы → commit → push на GitHub
→ Vercel видит изменения → собирает сайт → deploy → сайт обновлён
```

**Пример из твоей работы.** Клиент просит изменить часы работы. Ты просишь Claude Code: «Создай ветку `aggiorna-orari`, обнови часы работы, сделай commit и push». Vercel создаёт preview-ссылку, ты отправляешь её клиенту. Клиент говорит «ок» → ты объединяешь ветку с `main` → сайт обновлён.

**Хорошее сообщение коммита:** `Aggiorna orari di apertura estivi` (Обновлены летние часы работы).
**Плохое сообщение коммита:** `fix`, `update`, `asdf`.

✅ **Что нужно знать для работы**
1. Всё, что попало в `main`, обычно сразу публикуется на живом сайте.
2. Коммит — твоя «страховка»: если что-то сломалось, можно вернуться к прошлой версии.
3. Ветки + preview позволяют показать клиенту изменения до публикации.

❓ **Вопрос для самопроверки:** В чём разница между commit и push?
*(Ответ: commit сохраняет изменения у тебя локально, push отправляет их на GitHub.)*

⚠️ **Типичная ошибка:** Работать сразу в `main` и публиковать неподтверждённые изменения прямо на сайт клиента.

## 5. Vercel: автоматический деплой и preview
🇮🇹 *Vercel: deploy automatico e anteprima (preview)*

**Простое объяснение.** Vercel — это хостинг-платформа, которая «смотрит» на твой репозиторий GitHub. Как только ты отправляешь (push) изменения, Vercel сам:

1. скачивает код;
2. собирает его (🇮🇹 *build* / *compilazione*) — превращает исходники в готовые файлы;
3. публикует (deploy) на своих серверах по всему миру (CDN — 🇮🇹 *rete di distribuzione dei contenuti*).

**Два типа деплоя:**

| Тип | 🇮🇹 | Когда создаётся | Адрес |
|---|---|---|---|
| **Production** | *produzione* / *sito pubblico* | Push в ветку `main` | Основной домен клиента: `pizzeriadamario.it` |
| **Preview** | *anteprima* | Push в любую другую ветку или PR | Временная ссылка: `progetto-git-aggiorna-orari-tuonome.vercel.app` |

**Preview — твой главный инструмент продаж и согласования.** Ты можешь отправить клиенту ссылку и сказать:

🇮🇹 «Ecco l'anteprima delle modifiche. Se le approva, le pubblico oggi stesso.»
→ 🇷🇺 «Вот предварительный просмотр изменений. Если вы одобрите, я опубликую их сегодня же.»

**Важные функции Vercel:**
- **Rollback** (🇮🇹 *ripristino della versione precedente*) — откат к прошлому деплою одной кнопкой.
- **Environment variables** (🇮🇹 *variabili d'ambiente*) — секретные настройки (ключи API), которые не хранятся в коде.
- **Logs** (🇮🇹 *registri*) — журнал ошибок сборки.

> ⚠️ **Важно про тарифы.** Бесплатный план Vercel **Hobby** предназначен только для личного некоммерческого использования. Сайты клиентов — это коммерческое использование. Варианты: тариф **Pro** у тебя (с командой), или аккаунт Vercel на имя клиента. Проверяй актуальные условия на сайте Vercel.

**Пример из твоей работы.** Сборка «упала» (🇮🇹 *la build è fallita*). Ты открываешь Vercel → Deployments → видишь красный значок → открываешь логи → копируешь текст ошибки в Claude Code: «Вот ошибка сборки на Vercel, объясни простыми словами, что случилось, и исправь».

✅ **Что нужно знать для работы**
1. Push в `main` = изменения на живом сайте через 30–90 секунд.
2. Preview-ссылки — бесплатный способ показывать работу клиенту без риска.
3. Если что-то сломалось — сначала rollback (вернуть работающую версию), потом спокойно чинить.

❓ **Вопрос для самопроверки:** Клиент увидел ошибку на сайте в субботу вечером. Какое первое действие в Vercel?
*(Ответ: rollback к последнему работающему деплою.)*

⚠️ **Типичная ошибка:** Держать сайты платящих клиентов на бесплатном плане Hobby и нарушать условия использования.

## 6. DNS: записи A, CNAME, TXT, TTL и распространение
🇮🇹 *DNS: record A, CNAME, TXT, TTL e propagazione*

**Простое объяснение.** DNS (Domain Name System) — это «телефонная книга интернета». Она переводит имя (`pizzeriadamario.it`) в адрес сервера. Записи DNS (🇮🇹 *record DNS*) — это строки в этой книге.

| Запись | 🇮🇹 | Что делает | Пример для Vercel |
|---|---|---|---|
| **A** | *record A* | Указывает домен напрямую на IP-адрес | `@` → `76.76.21.21` (основной домен без www) |
| **CNAME** | *record CNAME* / *alias* | Указывает поддомен на другое имя | `www` → `cname.vercel-dns.com` |
| **TXT** | *record TXT* | Текстовая запись для проверки владения и почты | Подтверждение для Google Search Console, SPF для email |
| **MX** | *record MX* | Куда доставлять почту | `mx1.aruba.it` — **не трогать**, если почта клиента работает! |
| **TTL** | *tempo di vita* (Time To Live) | Сколько секунд другие серверы помнят запись, прежде чем спросить заново | `3600` = 1 час |

> Конкретные значения IP и CNAME всегда бери из панели Vercel (Settings → Domains): Vercel сам показывает, что нужно прописать.

**Почему распространение (🇮🇹 *propagazione DNS*) занимает время?**
Тысячи DNS-серверов в мире запоминают (кэшируют) ответ на время TTL. Если TTL был 24 часа, некоторые серверы будут показывать старый адрес до 24 часов. Обычно всё работает за несколько минут – пару часов, но официально «до 48 часов».

**Хитрость профессионала:** за день до переезда уменьши TTL до 300 секунд (5 минут). Тогда переключение пройдёт быстро.

**Пример из твоей работы.** У клиента домен и почта на Aruba. Ты меняешь **только** запись A для `@` и CNAME для `www`. Записи MX (почта) не трогаешь. Через час сайт открывается с Vercel, а почта клиента продолжает работать.

✅ **Что нужно знать для работы**
1. Перед изменением DNS сделай скриншот всех текущих записей — это твой бэкап.
2. MX-записи отвечают за почту: удалишь их — у клиента пропадёт почта.
3. Задержка после изменения DNS — нормально; это не ошибка.

❓ **Вопрос для самопроверки:** Почему нельзя «просто удалить все старые записи и добавить записи Vercel»?

⚠️ **Типичная ошибка:** Удалить MX- или TXT-записи (SPF/DKIM) при переносе сайта и сломать клиенту электронную почту. Это самая дорогая ошибка новичка — клиент может потерять заказы.

## 7. Домен vs хостинг vs сайт
🇮🇹 *Dominio vs hosting vs sito (perché il dominio può restare dove è)*

| | Домен | Хостинг | Сайт |
|---|---|---|---|
| 🇮🇹 | *dominio* | *hosting* | *sito web* |
| Что это | Имя/адрес | Место на сервере | Файлы: код, тексты, фото |
| Где покупается | Регистратор (🇮🇹 *registrar*): Aruba, Register.it, Namecheap, Cloudflare | Vercel, Netlify, Aruba, SiteGround | Создаёшь ты |
| Стоимость | ~10–25 €/год за `.it` | 0–20 €/мес для небольшого сайта | Твоя работа |
| Кто должен владеть | **Клиент** | Клиент или ты (по договору) | Клиент после оплаты (по договору) |

**Почему домен может остаться там, где он есть?**
Домен — это только «вывеска с адресом». Чтобы сайт работал на Vercel, домен не нужно переносить (🇮🇹 *trasferimento del dominio*) — достаточно поменять DNS-записи у текущего регистратора. Это:
- быстрее (минуты, а не дни);
- безопаснее (почта и другие сервисы клиента не страдают);
- проще для клиента (он ничего не теряет и не платит).

**Как объяснить клиенту:**

🇮🇹 «Il dominio resta suo e resta dov'è. Io cambio solo l'indirizzo a cui punta, come quando si aggiorna l'indirizzo sul navigatore.»
→ 🇷🇺 «Домен остаётся вашим и там, где он есть. Я меняю только адрес, на который он указывает, — как обновить адрес в навигаторе.»

✅ **Что нужно знать для работы**
1. Домен всегда регистрируется на имя клиента (или его фирмы).
2. Для подключения к Vercel достаточно изменить DNS, перенос домена не обязателен.
3. Почта клиента обычно привязана к хостингу/регистратору (Aruba) — уточняй это до работ.

❓ **Вопрос для самопроверки:** Клиент хочет уйти от тебя к другому веб-дизайнеру. Что должно остаться у него, чтобы переход был без проблем?

⚠️ **Типичная ошибка:** Регистрировать домен клиента на себя «для удобства». Это создаёт конфликт и недоверие, а в Италии — ещё и юридические риски.

## 8. SSL/HTTPS
🇮🇹 *SSL/HTTPS: perché serve e come si ottiene automaticamente*

**Простое объяснение.** HTTPS — это защищённое соединение между браузером и сервером. Данные шифруются (🇮🇹 *cifrati / crittografati*), и никто посередине (например, в публичном Wi-Fi) не может их прочитать или подменить. Замочек 🔒 в адресной строке = HTTPS работает.

**Зачем нужно:**
1. **Доверие.** Без HTTPS Chrome пишет «Non sicuro» (Небезопасно) — клиенты уходят.
2. **SEO.** Google понижает сайты без HTTPS.
3. **Закон.** GDPR (🇮🇹 *GDPR / Regolamento europeo sulla protezione dei dati*) требует защищать персональные данные — например, из контактной формы.

**Как получить:** На Vercel сертификат SSL (🇮🇹 *certificato SSL*) выпускается **автоматически и бесплатно** (через Let's Encrypt), как только домен правильно указывает на Vercel. Ничего покупать не нужно.

**Пример из твоей работы.** Ты подключил домен, но Vercel пишет «Invalid configuration» и замочка нет. Это почти всегда значит, что DNS ещё не распространился или записи указаны неверно. Подожди/проверь DNS — сертификат появится сам.

✅ **Что нужно знать для работы**
1. На Vercel HTTPS бесплатный и автоматический — никогда не продавай клиенту «SSL-сертификат за 50 €».
2. Сертификат выпускается только после правильной настройки DNS.
3. Проверяй, что `http://` автоматически перенаправляет на `https://` (на Vercel — по умолчанию).

❓ **Вопрос для самопроверки:** Почему у сайта может не быть HTTPS сразу после подключения домена?

⚠️ **Типичная ошибка:** Вставлять картинки или скрипты по `http://`-ссылкам — браузер показывает предупреждение о «смешанном содержимом» (🇮🇹 *contenuto misto*, mixed content).

## 9. Базовое техническое SEO
🇮🇹 *SEO tecnico di base*

**Простое объяснение.** SEO (Search Engine Optimization, 🇮🇹 *ottimizzazione per i motori di ricerca*) — это всё, что помогает Google понять сайт и показать его людям. Техническое SEO — это «правильно оформленные документы» сайта.

| Элемент | 🇮🇹 | Что это | Пример для пиццерии |
|---|---|---|---|
| **title** | *titolo della pagina* | Заголовок во вкладке и в выдаче Google, ~50–60 символов | `Pizzeria da Mario – Pizza napoletana a Verona Borgo Trento` |
| **meta description** | *meta descrizione* | Описание под заголовком в Google, ~150–160 символов | `Pizza napoletana cotta nel forno a legna. Asporto e consegna a Verona. Prenota: 045 123 4567.` |
| **H1** | *titolo H1* | Главный заголовок на странице, **один** на страницу | `Pizza napoletana a Verona` |
| **H2, H3** | *sottotitoli* | Подзаголовки разделов | `Il nostro menù`, `Dove siamo` |
| **alt** | *testo alternativo* | Описание картинки для Google и незрячих | `alt="Pizza margherita appena sfornata"` |
| **sitemap.xml** | *mappa del sito* | Список всех страниц для Google | `pizzeriadamario.it/sitemap.xml` |
| **robots.txt** | *file robots* | Инструкция для роботов: что можно сканировать | Разрешить всё, указать путь к sitemap |
| **Search Console** | *Google Search Console* | Бесплатный инструмент Google: как сайт виден в поиске, ошибки, запросы | Подключаешь для каждого клиента |

**Локальное SEO (🇮🇹 *SEO locale*)** — самое важное для малого бизнеса в Вероне:
- город и район в title и тексте («a Verona», «Borgo Trento», «San Zeno»);
- одинаковые название, адрес, телефон (NAP — Name, Address, Phone) на сайте и в Google Business Profile;
- профиль **Google Business Profile** (🇮🇹 *Scheda dell'attività su Google*) — часто приносит больше звонков, чем сам сайт;
- структурированные данные (🇮🇹 *dati strutturati*, schema.org `LocalBusiness`) — «паспорт» бизнеса для Google.

**Пример из твоей работы.** Промпт для Claude Code: «Для каждой страницы добавь уникальный title до 60 символов и meta description до 155 символов на итальянском, с упоминанием Вероны. Проверь, что на каждой странице ровно один H1. Добавь alt ко всем изображениям. Создай sitemap.xml и robots.txt. Добавь schema.org LocalBusiness с адресом и часами работы».

✅ **Что нужно знать для работы**
1. У каждой страницы — свой title и description, без дублей.
2. После запуска сайта — подключить Search Console и отправить sitemap.
3. Для местного бизнеса Google Business Profile так же важен, как и сайт.

❓ **Вопрос для самопроверки:** Что увидит человек в Google, если у страницы нет meta description?
*(Ответ: Google сам вытащит случайный кусок текста — часто неудачный.)*

⚠️ **Типичная ошибка:** Одинаковый title «Home» на всех страницах и картинки без alt.

## 10. Производительность (скорость)
🇮🇹 *Performance: perché un sito lento perde clienti*

**Простое объяснение.** Большинство клиентов малого бизнеса открывают сайт с телефона, часто на мобильном интернете. Если страница грузится дольше 3 секунд, значительная часть людей уходит. Google тоже учитывает скорость в ранжировании (метрики **Core Web Vitals** — 🇮🇹 *parametri web essenziali*).

**Что «весит» больше всего:**

| Элемент | 🇮🇹 | Типичная проблема | Решение |
|---|---|---|---|
| Изображения | *immagini* | Фото с телефона 5 МБ, 4000 px | Сжать, формат **WebP/AVIF**, ширина до ~1600–2000 px, цель — до 200–300 КБ |
| Видео | *video* | Фоновое видео 30 МБ на главной | Сжать, загружать с YouTube/Vimeo или убрать на мобильных |
| Скрипты (JS) | *script* | Слайдеры, чаты, трекеры, виджеты | Убрать лишнее, загружать отложенно (🇮🇹 *caricamento differito*) |
| Шрифты | *font* | 6 вариантов шрифта | 1–2 шрифта, 2–3 начертания |
| Сторонние сервисы | *servizi di terze parti* | Встроенная карта Google, Instagram-лента | Загружать по клику (🇮🇹 *al clic*) или как картинку со ссылкой |

**Ключевые понятия:**
- **Lazy loading** (🇮🇹 *caricamento pigro / differito*) — картинки внизу страницы грузятся, только когда до них долистали.
- **Кэш** (🇮🇹 *cache*) — браузер запоминает файлы, чтобы не скачивать их снова.
- **CDN** — копии сайта на серверах по всему миру; Vercel делает это сам.

**Инструменты проверки:** PageSpeed Insights (pagespeed.web.dev) — бесплатно, оценка 0–100. Цель для сайта-визитки: **90+ на мобильных**.

**Пример из твоей работы.** Клиент прислал 40 фото с телефона. До того как добавить их на сайт, попроси Claude Code: «Конвертируй все изображения в папке `/foto` в WebP, максимальная ширина 1600 px, качество 80, и добавь lazy loading».

✅ **Что нужно знать для работы**
1. Картинки — причина №1 медленных сайтов малого бизнеса.
2. Проверяй PageSpeed Insights до сдачи проекта и показывай результат клиенту — это аргумент продаж.
3. Каждый виджет (чат, Instagram, карта) — это цена в скорости.

❓ **Вопрос для самопроверки:** Почему нужно тестировать скорость именно в мобильном режиме?

⚠️ **Типичная ошибка:** Проверять сайт только на своём быстром Wi-Fi и мощном компьютере.

## 11. Доступность и итальянское законодательство
🇮🇹 *Accessibilità e normativa di base in Italia*

**Простое объяснение.** Доступность (🇮🇹 *accessibilità*) — это когда сайтом могут пользоваться все: слабовидящие (🇮🇹 *ipovedenti*), незрячие (🇮🇹 *non vedenti*, используют программы чтения с экрана — 🇮🇹 *screen reader*), люди с дальтонизмом, пожилые, люди, которые пользуются только клавиатурой.

**Основные правила:**

| Правило | 🇮🇹 | Как проверить |
|---|---|---|
| Достаточный контраст текста и фона (минимум 4.5:1 для обычного текста) | *contrasto sufficiente* | Сервис WebAIM Contrast Checker |
| Alt-текст для всех значимых картинок | *testo alternativo* | Каждая `<img>` с осмысленным `alt` |
| Правильные заголовки H1 → H2 → H3 | *gerarchia dei titoli* | Не прыгать с H1 на H4 |
| Работа с клавиатуры (Tab) | *navigazione da tastiera* | Пройди сайт клавишей Tab — видно ли, где ты? |
| Подписи у полей формы | *etichette dei campi* | У каждого поля есть `<label>` |
| Текст не меньше ~16 px, увеличение работает | *testo leggibile / zoom* | Увеличь до 200% — ничего не ломается? |
| Ссылки понятны вне контекста | *link descrittivi* | Не «clicca qui», а «Scarica il menù (PDF)» |

**Стандарты:** международный стандарт **WCAG 2.1/2.2 уровень AA** (🇮🇹 *Linee guida per l'accessibilità dei contenuti Web*) и европейский **EN 301 549**.

**Законодательство в Италии (кратко, информационно):**
- **Legge Stanca (L. 4/2004)** — закон о доступности; изначально для государственных органов. С 2020 года (DL 76/2020) распространён на крупные частные компании (оборот более 500 млн €).
- **European Accessibility Act** — в Италии введён **D.Lgs. 82/2022**, применяется с **28 июня 2025** к ряду продуктов и услуг, в том числе к **электронной коммерции**, банковским услугам, транспортным услугам. **Микропредприятия** (менее 10 сотрудников и оборот/баланс не более 2 млн €), оказывающие услуги, как правило, **освобождены** от требований к услугам.
- Надзор — **AgID** (🇮🇹 *Agenzia per l'Italia Digitale*).

**Что это значит для тебя:** большинство твоих клиентов (пиццерии, парикмахерские, мастера) юридически, скорее всего, не обязаны соответствовать требованиям. Но:
1. доступный сайт лучше для всех и лучше для SEO;
2. если клиент продаёт онлайн и он не микропредприятие — требования могут касаться его напрямую;
3. это хороший аргумент качества.

🇮🇹 «Il sito è progettato seguendo le linee guida di accessibilità WCAG: si legge bene anche da chi ha problemi di vista e funziona con lo screen reader.»
→ 🇷🇺 «Сайт сделан по рекомендациям доступности WCAG: его удобно читать людям с проблемами зрения, и он работает с программами экранного чтения.»

> ⚠️ Не обещай клиенту «полное юридическое соответствие» — это требует аудита. Говори «сделано с учётом рекомендаций WCAG».

**Также обязательно для любого сайта в Италии (GDPR и Garante Privacy):**
- **Privacy policy** (🇮🇹 *informativa sulla privacy*) — особенно если есть форма контакта.
- **Cookie policy** и **cookie-баннер** (🇮🇹 *banner dei cookie*), если используются нетехнические cookies (аналитика с идентификацией, рекламные пиксели, встроенные YouTube/Maps). Правила — «Linee guida cookie» Garante Privacy (2021): кнопка «Rifiuta» (отказаться) должна быть такой же заметной, как «Accetta».
- В подвале (🇮🇹 *footer*): название фирмы и **Partita IVA** (налоговый номер) клиента — обязательное требование для сайтов компаний в Италии.

✅ **Что нужно знать для работы**
1. Контраст, alt, заголовки, клавиатура, подписи полей — пять базовых проверок для каждого сайта.
2. Partita IVA клиента в подвале и privacy policy — обязательный минимум.
3. Если ставишь Google Analytics/Meta Pixel — нужен корректный cookie-баннер.

❓ **Вопрос для самопроверки:** Почему светло-серый текст на белом фоне — проблема, даже если «выглядит стильно»?

⚠️ **Типичная ошибка:** Ставить встроенную Google Карту и YouTube без cookie-баннера и без privacy policy.

## 12. Адаптивность и mobile-first
🇮🇹 *Responsive e mobile-first*

**Простое объяснение.**
- **Responsive design** (🇮🇹 *design responsivo / adattivo*) — сайт автоматически перестраивается под размер экрана: телефон, планшет, компьютер.
- **Mobile-first** (🇮🇹 *prima il mobile*) — проектировать сначала для телефона, потом расширять для компьютера. Причина: большинство посетителей сайтов малого бизнеса приходят с телефона, и Google индексирует в первую очередь мобильную версию (🇮🇹 *indicizzazione mobile-first*).

**Как это работает:** в CSS есть **медиа-запросы** (🇮🇹 *media query*): «если экран шире 768 px — покажи 3 колонки, иначе — 1 колонку». Точки перехода называются **breakpoints** (🇮🇹 *punti di interruzione*).

**Чек-лист mobile-first для малого бизнеса:**
- Кнопка «Позвонить» (🇮🇹 *Chiama*) и «WhatsApp» видны сразу, без прокрутки.
- Кнопки не меньше ~44×44 px — чтобы попасть пальцем.
- Адрес — ссылка на Google Карты («Indicazioni stradali»).
- Текст не меньше 16 px, нет горизонтальной прокрутки.
- Меню-«гамбургер» (☰) работает и закрывается.

**Пример из твоей работы.** Перед сдачей открой сайт в Chrome → F12 → значок телефона (Device Toolbar) → проверь iPhone SE (маленький экран) и iPad. И обязательно — на своём реальном телефоне.

✅ **Что нужно знать для работы**
1. Сначала телефон, потом компьютер.
2. Главное действие (позвонить, записаться, заказать) — в один тап.
3. Проверяй на реальном устройстве, а не только в эмуляторе.

❓ **Вопрос для самопроверки:** Что клиент парикмахерской хочет сделать в первые 5 секунд на сайте с телефона?

⚠️ **Типичная ошибка:** Делать дизайн на большом мониторе и «сжимать» его для телефона в последний момент.

## 13. Аналитика и отслеживание
🇮🇹 *Analytics e tracciamento: cosa misurare*

**Простое объяснение.** Аналитика (🇮🇹 *analisi dei dati / statistiche*) показывает, сколько людей приходит на сайт и что они делают. Для малого бизнеса важны не «красивые графики», а **конверсии** (🇮🇹 *conversioni*) — действия, которые приносят деньги.

**Что измерять:**

| Метрика | 🇮🇹 | Почему важно |
|---|---|---|
| Визиты | *visite / sessioni* | Приходят ли люди вообще |
| Источник трафика | *sorgente di traffico* | Google, Instagram, прямые заходы |
| Клики «Позвонить» | *clic sul numero di telefono* | Главная конверсия для услуг |
| Клики WhatsApp | *clic su WhatsApp* | Вторая главная конверсия |
| Отправка формы | *invio del modulo* | Запросы, бронирования |
| Клики «Маршрут» | *clic su indicazioni stradali* | Люди собираются прийти |
| Страницы | *pagine più visitate* | Что интересует клиентов |

**Инструменты:**
- **Vercel Web Analytics** — простая аналитика без cookies, встроена в Vercel. Хороший вариант с точки зрения приватности.
- **Plausible / Umami** — простые, приватные альтернативы.
- **Google Analytics 4 (GA4)** — мощная, бесплатная, но требует cookie-баннера и согласия.
- **Google Search Console** — по каким запросам находят сайт.
- **Google Business Profile → Статистика** — звонки и маршруты из Карт.

**Отчёт для клиента (раз в месяц)** — часть услуги ретейнера:

🇮🇹 «Questo mese il sito ha avuto 620 visite, 38 persone hanno cliccato per chiamarla e 12 hanno chiesto le indicazioni stradali.»
→ 🇷🇺 «В этом месяце на сайте было 620 посещений, 38 человек нажали, чтобы вам позвонить, и 12 запросили маршрут.»

✅ **Что нужно знать для работы**
1. Считай действия (звонки, WhatsApp, формы), а не только посещения.
2. Аналитика с cookies = нужен баннер согласия; аналитика без cookies — проще.
3. Ежемесячный короткий отчёт делает ценность ретейнера видимой.

❓ **Вопрос для самопроверки:** Сайт получил 1000 визитов и 0 звонков. Это хороший результат? Что проверить?

⚠️ **Типичная ошибка:** Ставить GA4 «на всякий случай», никогда туда не заходить и при этом не иметь cookie-баннера.

## 14. Базовая безопасность
🇮🇹 *Sicurezza di base*

**Простое объяснение.** Безопасность для тебя — это защита четырёх вещей: твоих аккаунтов, аккаунтов клиентов, кода и данных.

**Правила:**

| Правило | 🇮🇹 | Как |
|---|---|---|
| Менеджер паролей | *gestore di password* | Bitwarden, 1Password — уникальный длинный пароль для каждого сервиса |
| Двухфакторная аутентификация | *autenticazione a due fattori (2FA)* | Включить на GitHub, Vercel, Google, у регистратора домена, на почте. Лучше приложение (Authenticator), чем SMS |
| Резервные копии | *backup / copie di sicurezza* | Код — на GitHub (это уже бэкап). Фото и тексты клиента — отдельная папка в облаке. Скриншот DNS-записей |
| Доступы клиента | *accessi del cliente* | Клиент приглашает тебя как пользователя (🇮🇹 *utente delegato*), а не отдаёт свой пароль |
| Принцип минимальных прав | *privilegio minimo* | Давай/бери только те доступы, которые нужны |

**Что НИКОГДА нельзя публиковать (особенно в публичном репозитории GitHub):**
- ключи API (🇮🇹 *chiavi API*) — OpenAI, Anthropic, Stripe, Telegram bot token, Resend и т. п.;
- пароли, токены доступа (🇮🇹 *token di accesso*);
- файл `.env` (там хранятся секреты) — он должен быть в `.gitignore`;
- личные данные клиентов (заявки, телефоны, email из форм).

**Где хранить секреты:** в **Environment Variables** на Vercel (Settings → Environment Variables). В коде используется только имя переменной, например `process.env.TELEGRAM_TOKEN`.

**Если ключ случайно попал на GitHub:** удаление коммита **не помогает** (история и боты уже могли его скопировать). Нужно немедленно **отозвать ключ** (🇮🇹 *revocare la chiave*) в сервисе и создать новый.

**Пример из твоей работы.** Ты делаешь форму, которая отправляет заявки в Telegram. Промпт: «Токен бота храни в переменной окружения TELEGRAM_BOT_TOKEN, не пиши его в коде. Проверь, что `.env` есть в `.gitignore`».

✅ **Что нужно знать для работы**
1. 2FA на всех ключевых сервисах — обязательно.
2. Секреты — только в переменных окружения, никогда в коде.
3. Утёкший ключ — сразу отозвать, а не просто удалить из кода.

❓ **Вопрос для самопроверки:** Почему удаление файла с ключом из GitHub не решает проблему утечки?

⚠️ **Типичная ошибка:** Попросить ИИ «вставь мой ключ прямо в код, чтобы заработало» и сделать push в публичный репозиторий.

## 1. Модели дохода
🇮🇹 *Modelli di ricavo*

### 1.1. Разовый проект (сайт = единоразовый платёж)
🇮🇹 *Progetto una tantum*

**Суть:** клиент платит один раз за создание сайта.

| Пакет | 🇮🇹 | Что входит | Цена | Твоё время |
|---|---|---|---|---|
| Одностраничник | *sito one-page / landing page* | 1 страница: о нас, услуги, фото, контакты, карта | 400–800 € | 6–12 ч |
| Сайт-визитка | *sito vetrina* | 4–6 страниц, SEO-база, форма, privacy | 900–1 800 € | 15–30 ч |
| Сайт с редактируемым контентом | *sito con CMS / blog* | + блог/новости/меню, которые клиент меняет сам | 1 500–3 000 € | 30–50 ч |

- **Идеальный клиент:** бизнес без сайта или с очень старым сайтом: ресторан, парикмахерская, B&B, ремесленник (🇮🇹 *artigiano*), стоматолог, фитнес-студия.
- **Маржа (🇮🇹 *margine*):** очень высокая, 85–95% (почти нет расходов кроме твоего времени и инструментов).
- **Минус:** деньги приходят один раз. Чтобы зарабатывать, нужно постоянно искать новых клиентов.

### 1.2. Обслуживание и ретейнер (абонентская плата)
🇮🇹 *Manutenzione e retainer (canone mensile)*

**Суть:** клиент платит каждый месяц за то, что сайт работает, обновлён и защищён.

| Уровень | 🇮🇹 | Что входит | Цена/мес | Твоё время/мес |
|---|---|---|---|---|
| Базовый | *Assistenza base* | Хостинг/контроль работы, бэкап, обновления, 30 мин мелких правок | 40–70 € | 0,5–1 ч |
| Стандарт | *Assistenza standard* | + 1 ч правок, ежемесячный отчёт, проверка SEO | 80–150 € | 1–2 ч |

- **Идеальный клиент:** любой бизнес, у которого нет времени и желания заниматься сайтом.
- **Маржа:** 70–90%, если чётко ограничено время. Становится убыточной, если клиент просит «ещё одну мелочь» каждую неделю.
- **Плюс:** предсказуемый доход (🇮🇹 *entrate ricorrenti*) — основа устойчивого бизнеса.

### 1.3. Постоянный контент
🇮🇹 *Contenuti continui*

**Суть:** ты регулярно обновляешь тексты, фото, меню, акции, часы работы, публикации блога, товары.

- **Цена:** 150–400 €/мес (например, 2 статьи в блог + обновление меню + сезонные баннеры).
- **Время:** 3–8 ч/мес (Claude помогает с черновиками текстов, но проверка и фото — на тебе).
- **Идеальный клиент:** ресторан с сезонным меню, B&B, магазин, клиника, агентство недвижимости (🇮🇹 *agenzia immobiliare*).
- **Маржа:** 60–80%.

### 1.4. Автоматизации
🇮🇹 *Automazioni*

**Суть:** сайт не просто «висит», а работает на бизнес: заявки сами приходят в Telegram/email/CRM, клиент получает автоматический ответ, ИИ-ассистент отвечает на частые вопросы.

- **Цена:** настройка (🇮🇹 *setup / attivazione*) 200–800 € + 20–80 €/мес за поддержку.
- **Время:** 3–10 ч на настройку, 0,5 ч/мес на контроль.
- **Идеальный клиент:** бизнес, который теряет заявки или тратит время на одинаковые ответы: автосервис, стоматолог, салон красоты, школа языков.
- **Маржа:** 70–85% (учти стоимость сервисов: API ИИ, сервисы email, n8n/Make).

## 2. Расчёт устойчивости
🇮🇹 *Calcolo della sostenibilità*

### 2.1. Исходные данные (пример)

| Параметр | Значение |
|---|---|
| Цена ретейнера | 100 €/мес на клиента |
| Остаток после налогов и INPS (forfettario, первые 5 лет) | ~78% |
| Постоянные расходы (🇮🇹 *costi fissi*) | ~150 €/мес: Claude (подписка), Vercel Pro, домен/почта, менеджер паролей, коммерчиалист (~70 €/мес в среднем), телефон |
| Время на клиента в ретейнере | 1 ч/мес в среднем |

### 2.2. Сценарии: 0, 10, 25, 50 клиентов по 100 €/мес

| Клиентов | Оборот/мес | Оборот/год | После налогов (~78%) | Расходы/мес | **Чистыми в месяц** | Часов/мес | Эффективная ставка |
|---|---|---|---|---|---|---|---|
| 0 | 0 € | 0 € | 0 € | 150 € | **−150 €** | 0 | — |
| 10 | 1 000 € | 12 000 € | 780 € | 150 € | **630 €** | 10 | 63 €/ч |
| 25 | 2 500 € | 30 000 € | 1 950 € | 150 € | **1 800 €** | 25 | 72 €/ч |
| 50 | 5 000 € | 60 000 € | 3 900 € | 250 € * | **3 650 €** | 50 | 73 €/ч |

\* При 50 клиентах расходы растут (больше инструментов, мониторинг, возможно, помощник).

**Выводы:**
- Ретейнер сам по себе даёт **стабильную базу**, а проекты — **рост и рывки**.
- 50 клиентов × 1 ч = 50 ч/мес — это всего ~2,5 ч в день. Остальное время — на новые проекты и продажи.
- Не забывай: на 60 000 €/год ты близко к лимиту forfettario (85 000 €) вместе с проектами. Планируй с коммерчиалистом.

### 2.3. Сколько клиентов нужно для желаемого дохода

**Формула:**
```
Нужный оборот в месяц = (Желаемый чистый доход + Постоянные расходы) ÷ 0,78
Количество клиентов = Нужный оборот ÷ Цена ретейнера
```

**Пример:** ты хочешь 2 500 € чистыми в месяц.
(2 500 + 150) ÷ 0,78 ≈ **3 400 € оборота** → 34 клиента по 100 €/мес.

**Реалистичный микс (лучше):** 20 клиентов ретейнера (2 000 €) + 1 сайт в месяц по 1 400 € = 3 400 €.

### 2.4. Стоимость времени: когда ретейнер становится убыточным

Определи свою **минимальную ставку** (🇮🇹 *tariffa oraria minima*). Пример: 40 €/ч.

| Часов на клиента/мес | Стоимость твоего времени (40 €/ч) | Ретейнер 100 € | Итог |
|---|---|---|---|
| 0,5 ч | 20 € | 100 € | ✅ Очень выгодно |
| 1 ч | 40 € | 100 € | ✅ Выгодно |
| 2 ч | 80 € | 100 € | 🟡 На грани |
| 2,5 ч | 100 € | 100 € | 🟠 Точка безубыточности (🇮🇹 *punto di pareggio*) |
| 4 ч | 160 € | 100 € | 🔴 Убыток: −60 € в месяц |

**Правило:** записывай время на каждого клиента (Toggl, Clockify или простая таблица). Если 3 месяца подряд клиент занимает больше 2 ч/мес — пора:
1. поговорить и предложить более высокий тариф, или
2. выставлять доп. часы отдельно, или
3. автоматизировать то, что он просит постоянно (например, дать ему CMS для смены меню).

🇮🇹 «Negli ultimi tre mesi le richieste sono raddoppiate rispetto a quanto previsto dal pacchetto. Le propongo di passare al piano Standard, così ha più ore incluse e un prezzo orario più basso.»
→ 🇷🇺 «За последние три месяца запросов стало вдвое больше, чем предусмотрено пакетом. Предлагаю перейти на тариф “Стандарт” — так у вас будет больше включённых часов и ниже цена за час.»

## 4. Управление отношениями с клиентами
🇮🇹 *Gestione dei rapporti con i clienti*

### 4.1. Что входит в ретейнер, а что нет
🇮🇹 *Cosa include il retainer e cosa no*

Чёткая граница защищает тебя от «бесконечных просьб» (🇮🇹 *richieste infinite*), а клиента — от неожиданных счетов.

| ✅ Входит (тариф «Стандарт», 100 €/мес) | ❌ Не входит (оплачивается отдельно) |
|---|---|
| Контроль работы сайта и хостинга | Новые страницы или разделы |
| Обновление зависимостей и безопасности | Редизайн (🇮🇹 *restyling*) |
| Резервная копия и восстановление | Новые функции (бронирование, магазин) |
| До **1 часа** мелких правок в месяц: тексты, фото, цены, часы работы | Фотосъёмка, видео, написание статей |
| Продление SSL, проверка DNS | Реклама Google Ads / Meta |
| Ежемесячный короткий отчёт | Проблемы, вызванные изменениями третьих лиц |
| Ответ в течение **2 рабочих дней** | Срочные работы в выходные (тариф ×1,5) |

**Правила:**
- Неиспользованные часы **не переносятся** на следующий месяц (🇮🇹 *le ore non utilizzate non sono cumulabili*).
- Запросы — **в одном канале** (например, email или одна группа WhatsApp), не звонками в 22:00.
- Доп. работы — по ставке **45–60 €/ч**, после письменного согласия клиента.

🇮🇹 «Questa richiesta va oltre l'ora mensile inclusa nell'assistenza. La stimo in circa due ore, cioè 100 euro. Procedo?»
→ 🇷🇺 «Этот запрос выходит за рамки часа в месяц, включённого в обслуживание. Я оцениваю его примерно в два часа, то есть 100 евро. Приступать?»

### 4.2. Как работать с дополнительными правками
🇮🇹 *Come gestire le revisioni extra*

**В проекте:** включай **2 раунда правок** (🇮🇹 *2 giri di revisioni*). Раунд = клиент присылает **один список** изменений, ты вносишь все сразу.

**Процесс:**
1. Клиент получает preview-ссылку.
2. Присылает все правки одним сообщением (не по одной в день!).
3. Ты вносишь их → новая preview-ссылка.
4. После 2-го раунда каждый следующий — платный (например, 60 € за раунд или почасово).

🇮🇹 «Per lavorare in modo ordinato, le chiedo di raccogliere tutte le modifiche in un unico messaggio. Il preventivo include due giri di revisioni; quelli successivi li conteggio a parte.»
→ 🇷🇺 «Чтобы работать организованно, прошу вас собрать все изменения в одно сообщение. Смета включает два раунда правок; последующие я считаю отдельно.»

**Как отличить «правку» от «нового запроса»:**
- Правка: «поменяй цвет кнопки», «исправь опечатку», «замени фото».
- Новый запрос: «добавь страницу», «давай сделаем онлайн-бронирование», «а можно ещё английскую версию?».

🇮🇹 «Ottima idea! Non era prevista nel preventivo iniziale, quindi le preparo un piccolo preventivo a parte, così decide con calma.»
→ 🇷🇺 «Отличная идея! Её не было в первоначальной смете, поэтому я подготовлю небольшую отдельную смету, чтобы вы могли спокойно принять решение.»

### 4.3. Кто владеет доменом и аккаунтами — всегда клиент
🇮🇹 *Chi possiede il dominio e gli account: il cliente, sempre*

| Ресурс | Владелец | Твой доступ |
|---|---|---|
| Домен (Aruba, Register.it…) | Клиент (его имя / его фирма) | Доступ к DNS или делегированный пользователь |
| Google Business Profile | Клиент | Менеджер (🇮🇹 *gestore*) |
| Search Console / Analytics | Клиент | Пользователь с полными правами |
| Репозиторий GitHub | Твой (в работе) → передаётся клиенту по запросу после оплаты | — |
| Vercel | Аккаунт клиента **или** твоя команда Pro (указано в договоре) | — |
| Email-сервисы, API-ключи | На аккаунт клиента, если это его расходы | — |

**Почему так:**
1. Доверие: клиент знает, что не «в заложниках».
2. Безопасность: если с тобой что-то случится, бизнес клиента не остановится.
3. Профессионализм: так работают серьёзные агентства.

🇮🇹 «Tutto ciò che riguarda la sua attività, dominio, scheda Google e statistiche, resta intestato a lei. Io ho solo un accesso da collaboratore, che può revocare quando vuole.»
→ 🇷🇺 «Всё, что касается вашего бизнеса — домен, карточка Google и статистика, — остаётся оформленным на вас. У меня только доступ сотрудника, который вы можете отозвать в любой момент.»

**Документ при сдаче (🇮🇹 *documento di consegna*):** список всех сервисов, где что находится, кто владелец, как восстановить доступ. Отдай клиенту в PDF.

### 4.4. Базовые пункты договора (информационно, не юридическая консультация)
🇮🇹 *Clausole base del contratto (a titolo informativo, non legale)*

| № | Пункт | 🇮🇹 | Что указать |
|---|---|---|---|
| 1 | Предмет договора | *Oggetto del contratto* | Точный список работ: страницы, функции, языки |
| 2 | Сроки | *Tempi di consegna* | Дата сдачи, **при условии** получения материалов от клиента |
| 3 | Материалы клиента | *Materiali forniti dal cliente* | Тексты, фото, логотип — в течение X дней; задержка клиента сдвигает сроки |
| 4 | Цена и оплата | *Corrispettivo e modalità di pagamento* | Сумма, предоплата %, остаток, сроки оплаты, способ (bonifico) |
| 5 | Правки | *Revisioni* | Количество раундов, стоимость дополнительных |
| 6 | Интеллектуальная собственность | *Proprietà intellettuale e cessione dei diritti* | Права на сайт переходят клиенту **после полной оплаты**; библиотеки с открытым кодом — по их лицензиям |
| 7 | Права на материалы | *Responsabilità sui contenuti* | Клиент гарантирует, что имеет права на свои тексты/фото |
| 8 | Владение аккаунтами | *Titolarità di domini e account* | Домен и аккаунты — на имя клиента |
| 9 | Обслуживание | *Assistenza e manutenzione* | Что входит/не входит, время ответа, цена, длительность |

## 5. Автоматизация как услуга
🇮🇹 *Automazione come servizio*

### 5.1. Конкретные примеры

**А. Форма связи → уведомление в Telegram/email**
🇮🇹 *Modulo di contatto con notifica immediata*

- **Как работает:** посетитель заполняет форму → серверная функция на Vercel (🇮🇹 *funzione serverless*) отправляет сообщение в Telegram владельцу и копию на email (через сервис типа Resend) → посетитель получает автоматический ответ.
- **Ценность для клиента:** заявки не теряются в почте, ответ в течение минут.
- **Пример фразы:**
  🇮🇹 «Ogni volta che qualcuno compila il modulo, le arriva subito un messaggio su Telegram con nome, telefono e richiesta. Così può richiamare in pochi minuti, prima della concorrenza.»
  → 🇷🇺 «Каждый раз, когда кто-то заполняет форму, вам сразу приходит сообщение в Telegram с именем, телефоном и запросом. Так вы можете перезвонить за несколько минут — раньше конкурентов.»

**Б. Автоматический ответ клиенту**
🇮🇹 *Risposta automatica*

- Письмо: «Grazie, abbiamo ricevuto la sua richiesta, la ricontattiamo entro 24 ore» + полезная информация (цены, как добраться, что взять с собой).

**В. Заявки в таблицу / простую CRM**
🇮🇹 *Richieste salvate in un foglio Google o in un CRM*

- Каждая заявка — строка в Google Sheets или в CRM (HubSpot Free, Pipedrive): дата, источник, статус «перезвонили / записан / отказ». Клиент видит, сколько заявок принёс сайт.

**Г. Чат-бот для частых вопросов (FAQ) с ИИ**
🇮🇹 *Chatbot per le domande frequenti / assistente AI*

- Отвечает на основе информации о бизнесе: часы работы, цены, парковка, «вы делаете окрашивание?», «есть ли без глютена?».
- Если вопрос сложный — предлагает оставить контакт или написать в WhatsApp.
- ⚠️ Пользователь должен знать, что говорит с ИИ (требование прозрачности **EU AI Act**, применяется с августа 2026). Бот не должен выдумывать цены — давай ему только проверенные данные и проверяй ответы.
- Учитывай стоимость API ИИ в абонентской плате.

**Д. Напоминание об отзыве**
🇮🇹 *Promemoria per le recensioni*

- После визита (например, через 2 часа) клиент получает сообщение/email: «Grazie per essere stato da noi! Se si è trovato bene, ci lascerebbe una recensione?» + прямая ссылка на отзыв в Google.
- Больше отзывов → выше в Google Картах → больше клиентов. Очень легко продаётся.
- ⚠️ Нужно согласие на получение сообщений; нельзя «покупать» отзывы или давать скидку только за положительный отзыв (правила Google и законы о защите потребителей).

**Е. Напоминания о записи**
🇮🇹 *Promemoria degli appuntamenti*

- За 24 ч до визита — SMS/WhatsApp/email. Снижает неявки (🇮🇹 *appuntamenti mancati*) — для парикмахерских и стоматологов это прямые деньги.

### 5.2. Сколько брать

| Автоматизация | Настройка (🇮🇹 *setup*) | Абонентская плата (🇮🇹 *canone*) | Твоё время |
|---|---|---|---|
| Форма → Telegram/email + автоответ | 150–300 € | 10–20 €/мес (или в ретейнере) | 2–4 ч |
| Заявки → Google Sheets/CRM | 200–400 € | 15–30 €/мес | 3–5 ч |
| Напоминание об отзыве | 250–450 € | 20–40 €/мес | 3–6 ч |
| Напоминания о записи | 300–600 € | 30–60 €/мес (+ стоимость SMS) | 4–8 ч |
| ИИ-чат-бот FAQ | 400–900 € | 40–90 €/мес (вкл. расходы на API) | 6–12 ч |
| Пакет «Всё вместе» | 800–1 500 € | 80–150 €/мес | 15–25 ч |

**Как считать цену:** не по часам, а по **ценности** (🇮🇹 *valore*). Если напоминания экономят парикмахерской 4 неявки в месяц по 35 € — это 140 €/мес. Абонентская плата 40 €/мес — очевидная выгода.

🇮🇹 «Se i promemoria evitano anche solo quattro appuntamenti mancati al mese, lei recupera circa 140 euro. Il servizio costa 40 euro al mese: il conto è presto fatto.»
→ 🇷🇺 «Если напоминания предотвращают хотя бы четыре неявки в месяц, вы возвращаете около 140 евро. Услуга стоит 40 евро в месяц — посчитать несложно.»

# ПРИЛОЖЕНИЕ Б — 10 ПРАКТИЧЕСКИХ УПРАЖНЕНИЙ
🇮🇹 *10 esercizi pratici*

> Делай упражнения 1–5 **руками**, без ИИ — так ты действительно поймёшь основы. Потом попроси Claude проверить и объяснить, что можно улучшить.

**Упражнение 1 — Первая HTML-страница**
🇮🇹 *Crea una pagina HTML con un titolo e un paragrafo*
Создай файл `index.html` в обычном текстовом редакторе (VS Code). Напиши:
```html
<!DOCTYPE html>
<html lang="it">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Pizzeria da Mario – Verona</title>
</head>
<body>
  <h1>Pizzeria da Mario</h1>
  <p>La vera pizza napoletana nel cuore di Verona.</p>
</body>
</html>
```
Открой файл в браузере двойным щелчком. Объясни себе, что делает каждая строка (особенно `lang="it"` и `viewport`).

**Упражнение 2 — Структура страницы**
🇮🇹 *Aggiungi sezioni, elenco, immagine e link*
Добавь в страницу: раздел «Il nostro menù» (`<h2>`) со списком из 3 пицц (`<ul><li>`), картинку с осмысленным `alt`, ссылку для звонка `<a href="tel:+390451234567">Chiama ora</a>` и ссылку на WhatsApp `https://wa.me/39...`.

**Упражнение 3 — Стили CSS**
🇮🇹 *Dai stile alla pagina con il CSS*
Создай файл `style.css` и подключи его (`<link rel="stylesheet" href="style.css">`). Измени шрифт, цвет заголовка, сделай кнопку звонка зелёной, с отступами и скруглёнными углами. Проверь контраст кнопки в WebAIM Contrast Checker.

**Упражнение 4 — Немного JavaScript**
🇮🇹 *Aggiungi un comportamento con JavaScript*
Добавь кнопку «Mostra orari» (показать часы работы). При нажатии под ней появляется блок с часами, при повторном нажатии — скрывается. Подсказка: `element.hidden = !element.hidden`.

**Упражнение 5 — Адаптивность**
🇮🇹 *Rendi la pagina responsive*
Сделай блок из 3 карточек услуг: на телефоне — одна под другой, на экране шире 768 px — в ряд. Используй `@media (min-width: 768px)` и `display: grid` или `flex`. Проверь в Chrome DevTools (режим телефона) и на своём телефоне.

**Упражнение 6 — Git и GitHub с нуля**
🇮🇹 *Il tuo primo repository*
Создай репозиторий на GitHub, загрузи туда страницу из упражнений 1–5. Сделай 3 коммита с понятными сообщениями на итальянском. Затем создай ветку `nuovo-menu`, измени меню, сделай push, открой pull request и объедини его. Посмотри историю коммитов на GitHub и объясни, что в ней видно.

**Упражнение 7 — Деплой и откат на Vercel**
🇮🇹 *Pubblica e ripristina su Vercel*
Подключи репозиторий к Vercel. Сделай изменение в отдельной ветке и найди preview-ссылку. Объедини с `main` и проверь, что сайт обновился. Затем сделай **rollback** на предыдущую версию и обратно. Засеки, сколько секунд занимает каждый шаг.

**Упражнение 8 — SEO-аудит**
🇮🇹 *Fai un audit SEO di un sito reale*
Выбери сайт реального бизнеса в Вероне. Проверь (правая кнопка → «Просмотр кода страницы» и поиск в Google `site:домен.it`): есть ли title и description, один ли H1, есть ли alt у картинок, есть ли `/sitemap.xml` и `/robots.txt`, есть ли HTTPS и Partita IVA в подвале. Составь отчёт из 5 пунктов на итальянском, как будто для клиента.

**Упражнение 9 — Ускорение сайта**
🇮🇹 *Migliora la velocità*
Проверь свой сайт в PageSpeed Insights (мобильная версия) и запиши оценку. Возьми 5 фото с телефона, сожми их в WebP (сервис Squoosh или через Claude Code), добавь `loading="lazy"`. Проверь снова и сравни «до/после». Сохрани скриншоты — это будущий аргумент для клиентов.

**Упражнение 10 — Полный цикл продажи (симуляция)**
🇮🇹 *Simulazione di vendita completa*
Выбери один бизнес из своего списка с Google Карт. Подготовь:
1. сообщение первого контакта на итальянском;
2. демо главной страницы (макс. 2 часа) на preview-ссылке Vercel;
3. смету в трёх уровнях (База / Премиум / Премиум + Сервисы);
4. ответы на 3 самых вероятных возражения;
5. одну автоматизацию, которую ты предложишь этому бизнесу, с расчётом выгоды в евро.
